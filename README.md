# TSL-лендинг Artroflex Active — Италия, 60+

Одностраничный продающий лендинг на итальянском по ТЗ v1.0: 15 блоков, форма «Richiedi una chiamata», серверная передача лидов партнёру.

> Продукт: Artroflex Active, пищевая добавка, 30 капсул, 3 капсулы в день (2 в обед, 1 вечером) — упаковки хватает на 10 дней. Учесть при комплектации оффера.

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | Страница (все 15 блоков) |
| `assets/css/style.css` | Стили; цвета — переменные в начале файла |
| `assets/js/config.js` | **Все редактируемые данные**: название, цены, скидка, партнёр, утверждения |
| `assets/js/app.js` | Логика: утверждения, цены, таймер, слайдер, FAQ, форма, аналитика, cookie |
| `api/lead.php` | Приём заявки → валидация → партнёр (сервер-сервер) |
| `api/offer.php` | Серверное время, дата окончания акции, остаток |
| `api/config.php` | Серверные настройки (в git, без секретов); секреты — в `/home/artrofle/artroflex3-config.php` |
| `privacy.html`, `termini.html` | Черновики юридических страниц — **на согласование юристу** |

## Режимы

- **`mode: "draft"`** (сейчас) — видны все утверждения концепции с меткой «DA VERIFICARE» и жёлтые плейсхолдеры `[…]`. Для согласования с заказчиком.
- **`mode: "production"`** — видны только утверждения с `approvedClaims.<ключ> = true`; остальные заменяются нейтральным текстом или скрываются. Перед публикацией в тексте не должно остаться `[…]`.
- **Демо** — включается сам при открытии `index.html` с диска (или `demo: true`): заявки никуда не уходят, вверху чёрная плашка. Имя `errore` имитирует ошибку отправки.

## Развёртывание

Требуется хостинг с PHP 7.4+ и расширением cURL, HTTPS.

1. Залить все файлы в корень сайта.
2. В `api/config.php` указать формат API партнёра: соответствие полей (`map`), постоянные поля (`static`), домен в `allowed_origins`.
3. Секреты (токен Webvork, оффер, пароль редактора) — в `/home/artrofle/artroflex3-config.php`, см. раздел «Выкладка».
4. Каталог `_data` (служебные файлы, логи) — доступен PHP на запись, закрыт от веба (`.htaccess` уже есть; на nginx — `location /_data { deny all; }` и то же для `api/config.php`). Лучше вынести вне корня сайта через `data_dir`.
5. В `config.js`: `mode: "production"`, `offerId`, тексты, цены, `analytics.metaPixelId`.
6. Отправить тестовую заявку и проверить, что она появилась у партнёра (критерий приёмки).

### Как работает отправка

Форма → `api/lead.php`. Правила как в it2: имя — 2–60 символов после обрезки пробелов; телефон — префикс +39 фиксирован, вводится 10–11 цифр (лишние +39/0039/39 и 0 перед мобильным убираются), на сервер уходит `+39XXXXXXXXXX`, сервер проверяет `^+39d{10,11}$`. Далее honeypot → `lead_id` → Webvork (`api.webvork.com`, при сбое `api2`) → **успех пользователю только при `"status":"ok"` от Webvork**. Иначе — сообщение об ошибке, введённые данные сохраняются.

Повторная отправка той же формы (двойной клик, повтор после ошибки) использует тот же `request_id` — дубль не создаётся. Отдельной защиты от повторных заявок с того же телефона и лимита по IP нет (как в it2). Ошибки — в `_data/logs/ГГГГ-ММ.log` (телефон замаскирован).

## Как менять цену, скидку, таймер, остаток и тексты

| Что | Где |
|---|---|
| Цена, старая цена, доставка, доп. платежи | `config.js → price` |
| Процент скидки | `config.js → price.discountPercent` (при расхождении с фактической скидкой — предупреждение в консоли) |
| Цена после окончания акции | `config.js → price.afterExpiry` (`null` — цена скрывается) |
| Таймер акции | `config.js → offer.personalHours` (сейчас 5): персональная скидка на 5 часов с первого захода посетителя, при повторных заходах отсчёт продолжается. После окончания скидка, таймер и остаток скрываются. `0` — общая дата из `api/config.php → offer.ends_at` |
| Остаток упаковок | `api/config.php → offer.stock` + дата сверки `stock_updated_at`. Сверять с партнёром не реже раза в день во время рекламы. `0` — акция завершается |
| Выключить акцию досрочно | `api/config.php → offer.active = false` |
| Название, партнёр, реквизиты, сроки доставки | `config.js → text` |
| Включить согласованное утверждение | `config.js → approvedClaims` (после карточки в `docs/claims.md`) |
| Остальной текст, отзывы, эксперты, состав | прямо в `index.html` (блоки помечены комментариями `БЛОК N`) |
| Фото | заменить `<div class="media ph-media" style="aspect-ratio:…">` на `<picture>` с AVIF/WebP + JPEG, с теми же пропорциями. Ниже первого экрана — `loading="lazy"`, на главном — `fetchpriority="high"` и preload в `<head>` |

## Аналитика

События в `window.dataLayer`: `page_view`, `cta_click` (position), `form_start`, `form_submit`, `lead_accepted` (lead_id), `lead_error`. В Meta Pixel уходят только `PageView` и `Lead` (с `eventID = lead_id` для дедупликации с Conversions API) — **никогда не Purchase**, без имени и телефона. Пиксель грузится только после согласия в cookie-баннере.

Valid lead / Sale / Paid order / Return — по постбэкам партнёра во внутренней таблице по `lead_id`, с привязкой к дате лида. Формулы ROI — раздел 13 ТЗ.

## Что ждёт материалов заказчика

Все места `[В СКОБКАХ]` и пунктирные рамки фото: упаковка, фото людей, состав и инструкция, отзывы, эксперт, документы, цены, реквизиты, партнёр, API. Итальянский текст — вычитать носителю. Юридические тексты и основание обработки данных — юристу.

## Проверено

Вёрстка в браузере (320, 375 px, desktop), отправка формы через мок-сервер: ошибки полей, ошибка отправки с сохранением данных, тройной клик = одна заявка, UTM в заявке, таймер от серверного времени. **Не проверено**: PHP-бэкенд (на этой машине нет PHP), реальные смартфоны, интеграция с партнёром.

## Изображения

`assets/img/` — фрагменты, вырезанные из присланных креативов (без текста), в WebP + JPEG:
`hero-coppia` (первый экран), `prodotto-flacone`, `prodotto-confezione`.
Видео и кадр из него убраны по решению заказчика.

Упаковка на присланных изображениях выглядит как рендер и различается между креативами (на одном — оранжевая коробка). Перед публикацией заменить на фото реальной упаковки.

`.claude/launch.json` — только для локального предпросмотра (мок-сервер в PowerShell), на хостинг не загружать.

## Редактор отзывов

Адрес: `/admin/` (например `https://ваш-домен/admin/`). Пароль — `admin_password` в `/home/artrofle/artroflex3-config.php` (в репозитории его нет; пока не задан — вход закрыт). Пароль проверяется на сервере, 5 неверных попыток — блок на 15 минут, сессия живёт 4 часа.

- Добавление, удаление, порядок (↑ ↓), имя, возраст, город, текст, фото (загрузка до 3 МБ в `assets/img/reviews/`), видео mp4 и итальянские субтитры .vtt.
- На лендинге показываются только отзывы с отметками «Согласие автора получено» и «Опубликован». Без согласия опубликовать нельзя.
- Отзывы хранятся в `_data/reviews.json`. Сейчас там 10 пустых ячеек «Esempio N», ни одна не опубликована.
- Если опубликованных отзывов нет: в режиме `draft` видны заглушки из HTML, в `production` блок отзывов скрывается.

## Выкладка на хостинг (it3.artro-flex.com) через GitHub — схема как у ArtroFlexIT2

Каждый push в `main` выкладывает сайт по FTPS (`.github/workflows/deploy.yml`, загружаются только изменённые файлы). Вручную: **Actions → Deploy → Run workflow**.

### 1. Секреты GitHub (Settings → Secrets and variables → Actions → Secrets)

| Секрет | Значение |
|---|---|
| `FTP_SERVER` | `ftp.artro-flex.com` |
| `FTP_USERNAME` | `it3.artroflex@it3.artro-flex.com` |
| `FTP_PASSWORD` | пароль этого FTP-аккаунта |

Переменная `FTP_SERVER_DIR` (вкладка Variables) — не нужна: FTP-аккаунт it3 смотрит прямо в `/home/artrofle/it3.artro-flex`.

### 2. Файл секретов на сервере (один раз, вручную)

`artroflex3-config.php` (образец — `config.example.php`) загрузить в **`/home/artrofle/artroflex3-config.php`** — уровнем выше папки сайта, через cPanel → File Manager. Там: токен Webvork, `offer_id`, пароль редактора отзывов. В Git и в браузер файл не попадает, выкладка его не трогает.

Заявки уходят в Webvork так же, как у it2: `https://api.webvork.com/v1/new-lead`, при сбое — `api2.webvork.com`, поля `token`, `offer_id`, `name`, `phone`, `country=IT`, `lang=it`, `ip`, `utm_*`.

База данных `artrofle_artroflex3` не используется: отзывы и служебные данные хранятся в файлах `_data/`.
